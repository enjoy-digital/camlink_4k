# CamLink 4K Roadmap

How CamLink 4K is compared against the stock Elgato firmware, the gaps it closed and the new features
that could make it attractive to users (Done / Partial / Open). Phase history, current status and
hardware notes are in [PLAN.md](PLAN.md) and [HARDWARE.md](HARDWARE.md).

## 1. Benchmarking Against the Stock Firmware

The stock FX3 image of your unit (`camlink.py fx3-extract`) can be RAM-loaded, and it loads the
stock bitstream still present in flash: the same unit, cable and source can be tested with both
firmwares, switching in a few seconds and without writing the flash.

`software/bench.py` runs each test on both firmwares and writes the results to `doc/BENCHMARK.md`
(pacing, start/stop, time to first frame, CPU); latency is measured with the tools of
[LATENCY.md](LATENCY.md) and [COMPARISON.md](COMPARISON.md). Image quality metrics are not run yet.

### Metrics

| Metric                | Method                                                                                     |
|-----------------------|--------------------------------------------------------------------------------------------|
| Latency               | Source shows a frame counter / timestamp; the capture host decodes it and compares with its own clock. Requires the source and the capture on the same machine (Cam Link on the bench host's HDMI output). Also: device-side latency from PTS/SCR. |
| Frame pacing          | fps, jitter, dropped and duplicated frames from V4L2 buffer timestamps and frame counters, over long runs. |
| Image quality         | Same test content (colour bars, zone plate, fine text, gradients) captured by both: PSNR/SSIM vs reference, chroma accuracy, black/white levels, banding. |
| Modes and formats     | Resolutions, frame rates and pixel formats actually delivered for each input mode.          |
| Robustness            | Time to first frame, signal loss / cable replug, resolution change while streaming, 100+ start/stop cycles, host suspend. |
| Compatibility         | Linux without `UVC_QUIRK_FIX_FORMAT_INDEX`, Windows and macOS class drivers, OBS, browsers (WebRTC). |
| Host cost             | CPU load and USB bandwidth per format (YUY2 / NV12 / future compressed formats).            |

### Bench setup

- Automated: Cam Link HDMI input on a host output (the bench host's `HDMI-0`), content and timestamps
  generated by the capture host itself (`xrandr` modes + full screen test player).
- Manual/complementary: external sources (MacBook Pro 4K30, game consoles, cameras).
- Optional: YKUSH for power cycling, logic analyzer for I2C/timing investigations.

## 2. Improvements (Gaps vs Stock)

| # | Item                          | Status  | Description                                                                    |
|---|-------------------------------|---------|--------------------------------------------------------------------------------|
| 1 | Standalone boot               | Done    | FX3 image + bitstream in flash, boot watchdog, `flash-recover` (USB bootloader fallback), stock restore with `flash-write --force`. |
| 2 | 4K30 full resolution          | Done    | 4K30 NV12 through the DDR3 frame buffer (LiteDRAM DDR3-594 1:4) and 4K30 M420 (GPIF 100.8 MHz, 32KB DMA buffers). |
| 3 | Native 1080p60 input          | Done    | IT6802 SDR path, 1080p60 YUY2 captured at 60 fps (used for the latency measurements). |
| 4 | Audio (UAC)                   | Done    | HDMI I2S -> FPGA -> GPIF thread 1 -> UAC 1.0 48 kHz stereo, bit exact (alone and with 4K30 video); FX3 hangs covered by the FPGA watchdog. |
| 5 | Stream/signal robustness      | Partial | First frame fix and 20 start/stop cycles validated (`validate.py`); input change handling and "no signal" pattern implemented, signal loss / mode change not in the scripted validation. |
| 6 | Better downscaling            | Done    | 2x2 box filter (line buffer) for 4K -> 1080p instead of line dropping. A generic scaler is open. |
| 7 | Input-matched modes           | Partial | Requested mode served from any input (downscale, letterbox, center crop); dynamic descriptors following the input (as stock) are open. |

## 3. New Features (Not in Stock)

| Feature                         | Status  | Why it matters / state                                                       |
|---------------------------------|---------|------------------------------------------------------------------------------|
| Low-latency mode                | Done    | Lines streamed as received, no frame buffering at 1080p (frame to application 19 ms vs 46 ms stock), latency tools and low latency viewer ([LATENCY.md](LATENCY.md)). |
| Fixed output mode               | Partial | Any input delivered in the requested mode (downscale, letterbox, center crop): OBS scenes and calls do not break on input changes. No frame rate conversion. |
| 4K crop / zoom                  | Done    | Pixel-exact 1080p window anywhere in a 4K desktop (`camlink.py crop x y`, UVC Extension Unit). |
| Host-programmable EDID          | Partial | Own EDID (`software/edid.py`, 1080p60 + 2160p30) compiled into the firmware and loaded into the IT6802 EDID RAM at startup; runtime programming, extra modes (1440p, 1080p120) and EDID cloning are open. |
| Input information for apps      | Partial | Resolution, frame rate, colour space through the UVC Extension Unit (`uvc_xu.py info`) and `camlink.py hdmi-status`; audio format and hotplug events are open. |
| Accurate timestamps             | Partial | PTS/SCR from the FPGA clock in the UVC headers; A/V sync not characterized. |
| Colour controls                 | Partial | Brightness/contrast/saturation (UVC Processing Unit), RGB range (`camlink.py range`); levels and LUT are open. |
| DDR3 based features             | Open    | Freeze frame, frame-rate conversion, instant replay buffer.                   |
| 10-bit capture                  | Open    | To be evaluated: IT6802 20/24-bit 4:2:2 modes vs the 24 wired data lines.     |
| Self-test / test patterns       | Done    | Colour bars and "no signal" patterns, counter sources, `software/validate.py` (12 hardware steps). |
| Open, scriptable device         | Done    | CLI/API for automation (`software/camlink.py`), no vendor tools required.     |

## Open Questions

- Open: stock 4K30 NV12 throughput, how close to the FX3 limit does the stock firmware run?
- Open: IT6802 10-bit output mapping onto the 24 wired lines.
- Open: best host API for extension-unit controls (v4l2 controls via uvcvideo XU mapping vs vendor
  requests); today `software/uvc_xu.py` uses the uvcvideo XU ioctl.
